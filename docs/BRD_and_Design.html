2. Business overview

2.1 Problem statement

Data engineers spend much of their time reading unfamiliar SQL, profiling datasets, hand-writing validation checks and documenting pipelines. The work is repetitive, and results vary between people and projects.

2.2 Objectives

  • Cut the time to understand a query, profile a dataset and write validation checks.
  • Produce consistent, deterministic checks and documentation.
  • Run at zero cost with no mandatory paid service.
  • Submit a complete Skeleton Crew entry: one shared core, two distinct apps.
  • Leave a connector interface so warehouses can be added after the hackathon.

2.3 Users

UserNeed
Data engineer (primary)Quickly profile data, generate checks, understand and document SQL.
Analyst / QAValidate a dataset before using it in reports.
Hackathon judgesSee a working, well-designed, Kiro-driven project in under 3 minutes.

2.4 Success criteria

  • Both apps live on public URLs and usable end to end.
  • Profiler results match injected defects exactly in property tests.
  • Every generated check fails on bad data and passes on clean data.
  • App works with no LLM key.
  • Demo video under 3 minutes; repo has LICENSE and committed .kiro folder.

4. Scope

4.1 In scope (hackathon)

  • CSV upload and sample datasets (Retail, HR, Finance, Marketing).
  • Profiling, infection findings and score.
  • Generated checks in SQL, pytest and JSON; run-now in DuckDB.
  • SQL explain, lint, lineage; ETL documentation with Mermaid.
  • Optional free-tier LLM polish.
  • Zombie UI with Plain Mode.
  • MCP server and Kiro hooks.

4.2 Out of scope

  • Live warehouse or cloud connections (interface only).
  • Authentication, multi-user, scheduling, storage of user data.
  • Cost-based query optimization and guaranteed speedups.
  • Guaranteed correct foreign-key inference.
  • Files beyond a few hundred MB on the hosted app.

7.2 Data flows

Zombie Hunter: User uploads CSV(s) -> CSV connector loads into DuckDB -> profiler runs SQL aggregates -> rules convert results to infections -> UI shows score, zombies, drill-down -> testgen builds checks -> user downloads or runs them.

SQL Autopsy: User pastes SQL and picks dialect -> sqlglot parses -> analyzer extracts structure, lineage and lint findings -> template explanation built -> optional LLM polish -> docgen outputs Markdown + Mermaid.

7.5 Connector interface

class Connector:
    def list_tables(self) -> list[str]
    def get_schema(self, table) -> list[Column]
    def sample(self, table, n) -> DataFrame
    def query(self, sql) -> DataFrame

The profiler only calls query() with aggregate SQL, so a future warehouse connector reuses it unchanged.

7.6 Infection model

ZombieMeaningMeasured by
Ghost ZombieNull / missing valuesNull count per column
Clone ZombieDuplicate rows or keysDuplicate count by key or full row
Mutant ZombieType or format errorsValues failing type/format casts
Lost ZombieOrphaned foreign keysChild keys with no parent
Giant ZombieNumeric outliersValues outside IQR fences

Infection score = rows with at least one issue / total rows. The overlay appears above a configurable threshold (default 10%). Plain Mode hides all theming and shows the same findings as tables.

7.7 Generated test types

CheckExample SQL assertion
Not nullSELECT COUNT(*) FROM t WHERE col IS NULL -- expect 0
UniqueSELECT col FROM t GROUP BY col HAVING COUNT(*) > 1 -- expect none
Accepted valuesSELECT COUNT(*) FROM t WHERE status NOT IN ('A','B') -- expect 0
RangeSELECT COUNT(*) FROM t WHERE qty < 0 OR qty > 10000 -- expect 0
Referential integritySELECT COUNT(*) FROM child c LEFT JOIN parent p ON c.pid = p.id WHERE p.id IS NULL -- expect 0

7.8 SQL lint rules

RuleWhy it matters
SELECT *Reads unneeded columns; breaks when schema changes
Function on filtered columnCan stop partition pruning or index use
NOT IN with nullable subqueryReturns no rows if any value is NULL
Cross join / missing join conditionRow explosion
DISTINCT hiding join duplicatesMasks a faulty join

7.9 UX outline

  • Zombie Hunter: sidebar (domain, sample/upload, plain mode, threshold); main area (infection score, zombie counters, findings table, column drill-down, generated tests with download and run buttons).
  • SQL Autopsy: SQL input and dialect dropdown; tabs for Explanation, Issues, Lineage, Documentation; download button.
  • Overlay: full-screen, dismissible, disabled in Plain Mode and under reduced-motion.
